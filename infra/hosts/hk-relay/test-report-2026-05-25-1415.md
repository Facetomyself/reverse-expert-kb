## Interpretation

- All four HK node types worked through a real Mihomo core: Hysteria2, Reality, SOCKS, and HTTP.
- `hk-http` and `hk-reality` were the best-looking overall in this test set.
- `hk-hy2` is healthy, but not clearly faster from this OpenClaw-origin path.
- HTTP/SOCKS direct checks remained healthy after BBR + fq.
- The non-Cloudflare OVH object shows lower throughput than the Cloudflare test object, which indicates the remote content path/CDN matters a lot; this is not only a proxy protocol issue.
- These measurements are not representative of mainland ISP/mobile routes. For the original “HK optimized line” goal, the next discriminating check should run from an actual mainland client/network.

## Recommendation

- Keep BBR + fq enabled.
- Keep all four HK node types in the subscription for now.
- Prefer `hk-http` / `hk-reality` for TCP-sensitive default tests; keep `hk-hy2` available for lossy/mobile paths.
- Do not change Ali default selector yet based only on this OpenClaw-origin test.
- Next useful test: mainland client end-to-end throughput/latency against `hk-hy2`, `hk-reality`, `hk-socks`, `hk-http`.
