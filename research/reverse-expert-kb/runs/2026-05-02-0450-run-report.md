Primary durable split reinforced this run:

```text

```

Compact branch memory:

```text

```

Source-backed details:
- `unix(7)` frames AF_UNIX as local IPC with pathname, unnamed, and Linux abstract namespace sockets; pathname socket permissions and abstract namespace behavior are different proof objects.
- `SO_PEERCRED` returns connection-time peer credentials for connected AF_UNIX stream sockets/socket pairs, while `SO_PASSCRED` / `SCM_CREDENTIALS` gives per-message credentials when enabled and received as ancillary data.
- `SCM_RIGHTS` does not literally preserve the same integer fd; it duplicates a reference to an open file description into the receiver, often with a different descriptor number.
- Too-small or absent ancillary buffers can truncate/discard control data; `MSG_CTRUNC`, `RLIMIT_NOFILE`, `SCM_MAX_FD`, and close-on-exec handling can all decide whether the descriptor survives into the consumer path.
- `recvmsg(2)` / `sendmsg(2)` control data association matters; on Linux stream sockets, at least one byte of real data is required to send ancillary data, and ancillary data forms a barrier for stream receipt.
- Lower-surface fd-pass tracing is valuable, but sender-side fd-pass evidence is still weaker than receiver-side `recvmsg(...)`, dispatch, retention, and first-consumer proof.

## Reflections / synthesis

This was a useful native-branch addition because Unix-domain sockets often look deceptively simple in binaries: strings expose the socket name, xrefs expose `sendmsg` or `recvmsg`, and one credential check appears to explain authorization. In practice, the behavior-bearing object may be a passed fd or per-message credential, not the visible payload bytes.

The new workflow page should prevent six overreads:
1. **endpoint overread** — socket path or abstract name does not prove the current client/peer/run
2. **credential overread** — `SO_PEERCRED`, `SCM_CREDENTIALS`, and security labels answer different timing and identity questions
3. **payload overread** — received bytes do not prove ancillary control data survived or belonged to the same logical request
4. **fd-number overread** — `SCM_RIGHTS` transfers an open-file-description reference, not a stable integer fd identity
5. **trace overread** — sender-side fd-pass tracing does not prove receiver retention or handler use
6. **dispatch overread** — authorization/dispatch plausibility does not prove first handler-owned state/effect consumption

This gives the native branch a clean bridge between the D-Bus service note, service-dispatcher / worker-consumer note, callback/event-loop continuations, protocol ingress notes, and runtime evidence notes.
