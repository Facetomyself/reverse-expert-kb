## New findings

Primary durable split reinforced this run:

```text
service/characteristic discovered
  != characteristic properties prove this path is active
  != CCCD/subscribe write reached the peer for this connection
  != ATT Handle Value Notification / Indication observed for the expected value handle
  != host/mobile stack callback delivered this value
  != parser decoded the value under the right MTU/endianness/session assumptions
  != app/device state reducer or hardware effect consumed it
```

Compact branch memory:

```text
discovered != subscribed != notified/indicated != delivered != parsed != consumed
```

Source-backed details:
- Bluetooth / GATT material separates profiles, services, characteristics, values, descriptors, and client/server roles. For reverse work, that hierarchy is a contract selector, not behavior proof.
- ATT/GATT documentation and vendor docs separate notifications from indications; indication confirmation is stronger transport evidence than an unacknowledged notification, but still not final app-consumer proof.
- CCCD state is a frequent false stop: property bits, local descriptor state, peer descriptor writes, stack events, and later notifications must be kept separate, especially across reconnects, bonding, Service Changed events, and cache refresh.
- BLE practitioner material supports a two-surface workflow: inspect/log Bluetooth traffic and decompile the controlling mobile app so GATT exploration, packet/host-stack evidence, callbacks, parser helpers, and state reducers cross-check each other.

## Reflections / synthesis

This was a useful protocol-branch addition because BLE reverse engineering often starts with easy-looking GATT exploration output. The false certainty comes early: a custom UUID or notify property feels like the protocol answer, and a sniffer-visible notification feels like runtime proof. In practice, neither proves the state transition the analyst cares about.

The new workflow page should prevent six overreads:
1. **UUID overread** — service/characteristic discovery is candidate-contract selection only
2. **property overread** — notify/indicate capability is not subscription or emission proof
3. **CCCD overread** — setup is not later event delivery
4. **sniffer overread** — transport-visible value is not host/app callback proof
5. **callback overread** — mobile callback delivery is not parser semantics
6. **parser overread** — decoded fields are not state/effect ownership

The new page also gives the protocol branch a clean handoff into existing receive-ownership, parser-to-state, replay-gate, output-handoff, and hardware-effect pages once the BLE-specific subscription/delivery ambiguity is resolved.

## Concrete scenario notes or actionable tactics added this run

Added a concrete workflow with these tactics:
- freeze role, identity, bond/security state, connection, MTU, and app/firmware version
- select one service/characteristic/value-handle/CCCD contract rather than broad GATT inventory
- prove peer-side CCCD enablement for the connection of interest
- tie ATT notification/indication events to the expected value handle and preserve raw bytes
- cross the host/mobile callback boundary separately from parser semantics
- decode values under current endianness, length, MTU, sequence, and session assumptions
- require one state reducer, UI update, follow-on command, persistence/network write, actuator change, or hardware-side effect before claiming behavior ownership
