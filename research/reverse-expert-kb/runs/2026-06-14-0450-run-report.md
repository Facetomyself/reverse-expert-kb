## New findings
- `FltRegisterFilter(...)` and `FltStartFiltering(...)` are active-filtering evidence, not proof that the operation under analysis was selected, delivered, blocked, allowed, or surfaced to a user-visible effect.
- `FLT_REGISTRATION.OperationRegistration` and pre-operation callback entry prove only that a registered operation class was delivered to one callback for one instance/volume context; the callback return status still decides whether this is pass-through, post-callback request, pended work, or immediate completion.
- `FLT_PREOP_PENDING` is a distinct ownership boundary: the minifilter retains control until a worker calls `FltCompletePendedPreOperation(...)`. This makes queue/cancel/correlation evidence first-class, especially for scanner-style workflows.
- `FltCreateCommunicationPort(...)`, `FilterConnectCommunicationPort(...)`, and `FltSendMessage(...)` expose the user-mode policy-service seam, but message traffic is weaker than a correlated reply, decoded verdict, timeout/fallback posture, and later kernel-side completion/resume status.
- `FLT_PREOP_COMPLETE` plus `IoStatus.Status` can halt lower-stack/file-system processing, but even this is weaker than proving the caller-visible status, file-system side effect, alert/quarantine/log, or later policy consumer.
- The compact split added this run is: **registered != operation-selected != pre-callback-entered != pended/sent != replied/decided != completed/resumed != effect-owned**.

## Reflections / synthesis
The native branch had ETW and EndpointSecurity telemetry/policy evidence pages, plus several Windows IPC and service-helper pages, but it lacked a narrow Windows file-system filter-driver note for the common EDR/AV/DLP shape where the proof object moves from kernel callback into user-mode verdict service and back into kernel completion.

The practical correction is:

```text
loaded or registered minifilter
  != attached active instance for this volume
  != selected operation delivered to pre-op/post-op callback
  != policy context / scan request built from trustworthy fields
  != I/O pended or message sent to user mode
  != correlated user-mode reply / local decision received
  != IoStatus / FltCompletePendedPreOperation applied
  != caller-visible or policy-owned effect
```

This note should stop operators from overreading `.sys` presence, operation tables, callback hits, or `FltSendMessage` traffic as proof of a block/allow decision. It also creates a clean handoff: if the decisive proof object is user-mode IPC beyond the minifilter port, route to ALPC / named-pipe / COM / service-worker notes; if the filter only emits telemetry, route to ETW/runtime-evidence; if the case is malware/EDR-shaped, freeze kernel/user-mode verdict proof before moving to consequence or reporting pages.
