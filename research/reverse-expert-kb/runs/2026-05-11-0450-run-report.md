## Reflections / synthesis

Recent autosync runs deliberately rotated through protocol / firmware and native service-helper seams. The malware branch already had strong Windows persistence/hijack leaves and several Linux persistence leaves for `systemd`, cron/anacron, `udev`, and XDG autostart, but it lacked a Linux dynamic-linker hijack leaf with the same proof-object discipline as AppInit DLLs or DLL search-order hijacking.

The external sources make the split practical:
- the `ld.so(8)` manual separates loader behavior, preload scope, dynamic string expansion, search/path behavior, and secure-execution constraints
- MITRE frames dynamic-linker hijacking as execution-flow hijack via environment variables/files that load attacker libraries during process preparation
- practitioner reporting highlights that `/etc/ld.so.preload` and `LD_PRELOAD` have different scope, userland tools can be distorted, and real cases often depend on interposed functions such as directory, process, network, or authentication-related wrappers

The resulting KB delta is not “LD_PRELOAD exists.” It is a reverse-analysis stop rule: prove one target process accepted and loaded the object, then prove one interposed call and one effect, before writing a durable behavior claim.
