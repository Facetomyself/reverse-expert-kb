## New findings
- Apple's background URLSession model separates task creation from later app relaunch and delegate delivery. A background transfer can progress outside the foreground app, so task creation or `resume` is not app-owned result consumption.
- `application(_:handleEventsForBackgroundURLSession:completionHandler:)` is reattachment truth: it gives the app a session identifier and completion handler for background URL session events, but it does not itself prove that a task result was parsed, persisted, surfaced, or used.
- `urlSessionDidFinishEvents(forBackgroundURLSession:)` is delegate-drain truth: it tells the delegate that all queued messages for a background session were delivered. It is weaker than proving the stored app-delegate completion handler was called and weaker than proving the first app-owned file/state/result consumer.
- `sessionSendsLaunchEvents` and exact background-session identifier reuse make missing callbacks setup/configuration-shaped until ruled out. No-callback behavior should not be overread as target suppression before identifier, reattachment, and launch-event posture are checked.
- Forum/issue traces reinforce the practical implementation shape: store the app-delegate completion handler, recreate/reattach a background session with the same identifier, wait for session delegate event drain, then call the stored handler. These traces were used as implementation cues, not as substitute authority.
- The compact split added this run is: **created != progressed != relaunched != delegate-drained != completion-called != result-consumed**.

## Reflections / synthesis
The iOS branch already had a broad practical ladder for topology, environment, trust-path, URL-loading interception, owner localization, Swift-concurrency continuation, and result-to-policy proof. The under-described seam was narrower and common in real app work:

```text
created/resumed background URLSession task or relaunch callback == app-owned result behavior
```

The source-backed correction is smaller:

```text
background task created
  != system/daemon accepted and progressed transfer
  != app relaunched for the same session identifier
  != queued delegate events delivered
  != app called the stored completion handler
  != app parsed/consumed the result or produced a durable effect
```

This keeps background transfer work adjacent to, but not redundant with, URL-loading interception and Swift continuation notes. If the missing proof is custom protocol selection, route to URL-loading interception. If the missing proof begins after delegate delivery in Swift `Task` / `AsyncStream` / MainActor state, hand off to the Swift-concurrency branch.
