## New findings
- Apple’s archived Notifications guide keeps producer and observer ownership separate: notifications are broadcast through a center, a poster does not need to know observers, and payload identity is a `name`, `object`, and optional `userInfo` dictionary. This makes notification-name discovery weak evidence until producer post and observer consumption are both proved.
- Apple’s registration guide keeps local observer eligibility concrete: `addObserver:selector:name:object:` registers an observer, selector, name filter, and object filter; name or object may be omitted; multiple observer messages for the same notification can fire in an unspecified order; observer removal/lifetime matters.
- Block observers add a separate token/queue seam: `addObserver(forName:object:queue:using:)` creates/returns an observer object and runs the block on the chosen queue. Queue-mediated delivery can break naive producer-call-stack proof.
- Distributed notifications add a cross-process delivery seam: the object argument is an identifying string rather than an arbitrary object pointer, `NSApplication` may suspend delivery while inactive, and suspension behavior / deliver-immediately / post-to-all-sessions options can decide whether a target callback ever fires.
- The compact split added this run is: **name visible != posted != matched != delivered != observer entered != consumed/effected**.

## Reflections / synthesis
This run intentionally stayed out of browser/mobile density and did not add another Windows service or protocol leaf. The native branch already had good AppKit target/action, XPC helper, Qt/GUI, and generic callback-delivery pages; what was missing was a narrow Foundation notification seam that operators hit often in Apple desktop apps:

```text
notification constant or observer registration == behavior proof
```

The source-backed correction is narrower:

```text
producer posted this name/object/userInfo tuple;
a live observer matched it;
delivery actually happened under queue/coalescing/suspension rules;
this selector/block entered with the received payload;
this first observer-owned state/task/effect predicts the later behavior.
```

That split matters most in distributed-notification cases because sender-side proof is especially tempting but weak: a cross-process post can be visible while the target process is inactive, suspended, coalescing, dropping, or simply lacking a live matching observer.
