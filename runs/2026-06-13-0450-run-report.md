## New findings
- EndpointSecurity import or `es_new_client(...)` is only client-creation truth. It does not prove the target is currently subscribed, eligible, receiving messages, responding, logging, or enforcing policy.
- `es_subscribe(...)` provides event-interest truth and is cumulative, but an event enum in a subscription array is weaker than proving a concrete event was generated and delivered to the handler.
- `es_message_t` / handler entry is delivery truth. It needs to be tied to `event_type`, action kind, process/target fields, sequence/deadline where available, and then followed to the first reducer, queue, XPC handoff, alert/log writer, or response call.
- AUTH and NOTIFY paths must not be flattened: AUTH cases need `es_respond_auth_result(...)` / flags-response proof, result value, response deadline posture, and cache implications; NOTIFY cases are usually telemetry/reducer proof unless a later consumer takes enforcement action.
- Cache, mute, subscription, entitlement/client-state, event-type availability, and deadline behavior are first-class false-stop classes for missing or inconsistent handler evidence.
- The compact split added this run is: **client != subscribed != event-generated != delivered != responded/logged != policy-consumed/effected**.

## Reflections / synthesis
The native Apple branch had useful pages for XPC helpers, ServiceManagement, Cocoa responder chains, and NotificationCenter delivery, but it lacked a narrow EndpointSecurity page for security-event monitoring and policy-consumer proof.

The practical correction is small but important:

```text
EndpointSecurity framework/import/client creation
  != event subscription and client eligibility
  != one representative kernel/security event generated
  != message delivered to the handler
  != AUTH response or NOTIFY logging/reducer action
  != mute/cache/deadline state understood
  != target-owned policy/enforcement/telemetry effect
```

This note should stop operators from overreading EndpointSecurity symbol inventory, event arrays, or handler entry as proof of enforcement. It also creates a clean handoff: if the handler forwards to a helper, route to the macOS XPC helper seam; if it emits a rule or detection, route to malware/reporting/detection-rule handoff; if it only proves trace delivery, route to runtime-evidence packaging.
