## New findings
Primary durable split reinforced this run:

```text
NSEvent queued / sendEvent visible
  != control or menu item emitted action
  != explicit target or nil-target resolution truth
  != exact receiver on the current responder chain
  != first durable write / mode change / task enqueue
  != later visible consequence truth
```

A smaller selector-shaped split reinforced this run:

```text
selector name visible
  != current responder chain will accept it
  != targetForAction / sendAction receiver truth
  != first behavior-changing consumer
```

Concrete practical reinforcements preserved in the KB:
- Apple’s event-architecture and main-event-loop material preserves that `NSApplication` fetches events, converts them to `NSEvent`, dispatches them with `sendEvent:`, and usually forwards toward the relevant window/view or first responder; that is strong support for treating `sendEvent:` as framework reduction rather than automatic consumer proof
- Apple’s AppKit material preserves that `NSControl sendAction:to:` asks `NSApplication` / `NSApp` to deliver the action; that grounds `sendAction:to:from:` as the practical action-emission boundary rather than a generic selector-visibility fact
- Apple’s target/action documentation preserves the nil-target search order across key-window responder chain, window/delegate, main-window responder chain, and finally app/app-delegate; that is a concrete reason to keep `target == nil` separate from receiver truth
- retained `NSResponder` material preserves that untargeted actions search the larger action-message responder chain rather than the narrower ordinary event path; that keeps event-routing truth separate from action-routing truth
- retained `NSResponder` material also preserves that `targetForAction:` can recover the recipient of an untargeted action without sending it; that makes `targetForAction:` / `sendAction:to:from:` a practical smaller proof surface for reverse cases where selector names alone still lie
- Apple’s target/action material keeps sender/query semantics explicit; that grounds the practical rule that sender visibility is useful but still weaker than first durable consumer truth

## Concrete scenario notes or actionable tactics added this run
- if `sendEvent:` is the easiest global hook, ask whether it is only framework reduction and whether `sendAction:to:from:` is the first honest boundary instead
- if `target == nil`, freeze key-window, main-window, first-responder, and delegate state before narrating receiver ownership
- if many responders implement the same selector, hook or log `targetForAction:` together with `sendAction:to:from:` instead of guessing from selector names alone
- preserve one narrow chain: event routing -> action emission -> target resolution -> exact receiver -> first durable consumer
- do not treat sender visibility as consumer truth when the receiver still only validates, forwards, or chooses a later worker/document path
