## New findings
Primary durable split reinforced this run:

```text
dispatcher connected
  != ServiceMain entered
  != handler registered / accepted-controls truth
  != control-handler invocation
  != worker handoff / retained task truth
  != first worker-owned consumer

```

A second status-shaped split reinforced this run:

```text
SERVICE_START_PENDING / SERVICE_RUNNING / SERVICE_STOP_PENDING posture
  != worker-owned task/thread/callback ownership
  != later behavior-changing effect
```

A third control-handler split reinforced this run:

```text
handler entry visible
  != handler itself owns the work
  != worker handoff proved
  != first worker-owned consumer proved
```

Concrete practical reinforcements preserved in the KB:
- `StartServiceCtrlDispatcherW` preserves that the main thread becomes the service control dispatcher and does not return until all running services in the process have entered `SERVICE_STOPPED`
- the same documentation explicitly preserves that the dispatcher may create a new thread to execute `ServiceMain`, which is strong support for separating dispatcher truth from later service-owned worker truth
- `RegisterServiceCtrlHandlerEx` preserves that `ServiceMain` should immediately register the handler and that registration must occur before the first `SetServiceStatus`, because the handler must already be in place before accepted controls are advertised
- `Writing a ServiceMain Function` preserves that `SERVICE_START_PENDING` is initialization posture, that controls are usually not accepted during initialization, and that the sample only advertises controls after initialization reaches `SERVICE_RUNNING`
- `Service Control Handler Function` preserves that the handler runs in the context of the control dispatcher, must return within 30 seconds, and should move lengthy work to a secondary thread
- `Service State Transitions` preserves the still-sharper Vista-and-later reminder that lengthy control handling should move to a thread-pool worker, making handler entry weaker than worker-owned consumer proof
- `SetServiceStatus` preserves that SCM-visible state is interaction truth, that status can be reported from any service thread, and that `SERVICE_STOPPED` is a terminal practical boundary after which no further work should be assumed from the live service path

- if `StartServiceCtrlDispatcher*` is the first easy anchor, explicitly ask whether it is only dispatcher-connection truth and which later `ServiceMain` / worker path actually matters
- if `ServiceMain` is visible, freeze whether handler registration and accepted-controls posture are already proved before narrating worker ownership
- if `SetServiceStatus(...SERVICE_RUNNING...)` is visible, treat it as SCM interaction truth first, not automatic proof that the decisive worker path is already reduced
